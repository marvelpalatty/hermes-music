Privacy Policy

This policy describes the personal-use Hermes Music integration maintained by marvelpalatty. It is intended for the account owner’s private assistant, not public account registration.

Data accessed and purpose

With the owner’s Google authorization, the integration uses the YouTube Data API to read channel identity, owned playlists and their metadata/items, and liked videos. Relevant fields include channel and video identifiers, titles, playlist descriptions, privacy status, item counts, positions and uploader names. The purpose is to answer the owner’s questions and help organize their media.

Public music searches use the public YouTube Music catalog. The current OAuth integration does not access Music-specific saved songs/albums/artists, listening history or personalized recommendations.

Permissions and changes

The owner has authorized the broad YouTube OAuth scope to allow an owner-approved editing workflow. The currently deployed tools expose reads only. Future enabled playlist or rating changes must follow the owner’s specific command or approval. Google’s consent permissions are broader than the presently exposed tools.

Storage and security

OAuth client credentials and access/refresh tokens are stored on the owner’s private server in service-user-owned files with restrictive permissions. They are not published to this website or its public GitHub repository. These credential files are plaintext on disk; this application does not claim that its current storage, disk or backups are encrypted.

Credential entry is performed through an encrypted SSH session. Google API calls use HTTPS. Administrators, compromised processes with the service account’s privileges, or people with readable backup copies may be able to access stored credentials.

Assistant processing and sharing

When the owner asks the assistant to work with account data, relevant API results may enter the owner’s Hermes conversation history and logs and may be sent to the configured AI/model provider to fulfill that request. Retention and processing by those services depend on the owner’s configuration and the providers’ policies. Credentials are kept out of ordinary tool results and are not intentionally sent as conversation content.

This personal integration does not sell Google user data or use it for advertising. It does not intentionally use Google user data to train general-purpose AI models. Data is used to provide the owner-requested functionality. The application’s use of information received from Google APIs is subject to the Google API Services User Data Policy, including its Limited Use requirements.

Retention and deletion

OAuth credentials are retained on the private server until removed by the owner or operator. Access tokens are renewed using the saved refresh token while authorization remains valid. API results may remain in conversation records, logs or backups according to the owner’s retention settings; revoking Google access does not automatically erase those copies.

The owner can request deletion of local credentials and applicable retained records. Removing live files does not automatically remove existing backup copies; backups must be handled separately.

Revoking access

The owner can review and revoke this application’s Google access at Google Account connections. Revocation stops future authorized access but does not itself delete previously retained records.

This public website

This informational site is hosted on GitHub Pages. It contains no credential form, account login, music-library upload, application analytics script or advertising script. GitHub may process ordinary website-request information under the GitHub Privacy Statement.

Contact and updates

Contact the maintainer through the project’s GitHub issues. Do not include credentials or private account data in public issues. Policy changes are recorded in the public repository’s revision history.
